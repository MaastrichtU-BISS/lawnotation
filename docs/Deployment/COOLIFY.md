# Lawnotation on Coolify

The branch `feature/coolify-deployment` runs Lawnotation without Supabase or
Vercel, on the BISS Coolify (server **rice**), at
<https://next.lawnotation.org>. The production setup (Vercel +
Supabase, `app.lawnotation.org`) is untouched and keeps running; moving data
and users over and switching the domain is a later, separate step.

```
browser ──► app (Nuxt/Nitro, node)  next.lawnotation.org
              │  session cookie, own OIDC client
              ├──► Keycloak, realm lawnotation   auth.lawnotation.org (shared, not in this stack)
              ├──► IAA service                    iaa.lawnotation.org  (existing, not in this stack)
              ▼
            db (Postgres 17)  ◄── migrate (one-shot)   ◄── backup (nightly pg_dump)
              └── on the shared `coolify` network as lawnotation-postgres (pgAdmin)
```

## What replaced what

| Before (Vercel + Supabase) | Now |
|---|---|
| Vercel serverless function running the Nuxt server | the same Nuxt server in a container (`lawnotation-ui/Dockerfile`) |
| Supabase Postgres + PostgREST (supabase-js `.from()`, `.rpc()`) | plain Postgres 17; the server queries it with postgres.js (`ctx.sql`) |
| `supabase/migrations` | `lawnotation-ui/db/migrations`: `0001_baseline.sql` is the public schema those migrations produce, without the Supabase parts; `0002_oidc_users.sql` adds sign-in columns. Applied by `scripts/migrate.mjs` on every deploy |
| Supabase Auth (email OTP, magic links, `auth.users`) | Keycloak realm `lawnotation` (email + one-time code, its own mail), via `caselaw-auth/server`; the app keeps a signed httpOnly session cookie |
| `handle_new_user()` trigger on `auth.users` | `resolveUser()` in `server/utils/auth.ts`: links a users row to a Keycloak account by `oidc_sub`, or by verified email (invited annotators, migrated users), or creates a new editor |
| `auth.users.raw_user_meta_data` | `users.metadata` (onboarding hints, invitation flag) |
| `inviteUserByEmail` | the users row is created ahead of sign-in; the app emails the person if `SMTP_URL` is set |
| Supabase Studio | pgAdmin (the shared instance on rice) |
| Row level security (enabled, no policies) | none; every request is authorized in the tRPC authorizers, as before |

There were no Supabase cron jobs, Edge Functions, Storage buckets or Realtime
subscriptions, and no Vercel cron jobs, so nothing else had to move.

## Coolify resource

- Project **Lawnotation**, environment `production`, application `lawnotation`
  (Docker Compose build pack), public repository
  `https://github.com/MaastrichtU-BISS/lawnotation`, branch
  `feature/coolify-deployment`, compose file `/docker-compose.coolify.yml`.
- Domain: `https://next.lawnotation.org:3000` on the `app` service. The
  `lawnotation.org` zone (Vercel DNS) has a wildcard A record to rice, so no
  DNS change was needed.
- Pushes to the branch don't deploy by themselves (public repository without a
  webhook): use **Deploy** in Coolify.
- `lawnotation-ui/vercel.json` turns off Vercel builds for this branch, so the
  Vercel project never builds it against the production Supabase settings.

### Environment variables

| Variable | Value |
|---|---|
| `SERVICE_PASSWORD_POSTGRES`, `SERVICE_PASSWORD_64_SESSION` | generated by Coolify on the first deploy; don't change them |
| `AUTH_CLIENT_SECRET` | the `lawnotation` client's secret (Keycloak → realm lawnotation → Clients → lawnotation → Credentials) |
| `IAA_API_KEY` | the same key as the **Lawnotation IAA** application |
| `LAWNOTATION_URL`, `AUTH_ISSUER`, `AUTH_CLIENT_ID`, `IAA_SERVICE_URL` | empty = the compose defaults (`https://next.lawnotation.org`, the lawnotation realm, `lawnotation`, `https://iaa.lawnotation.org`) |
| `NOINDEX` | empty = `true`: every response has `X-Robots-Tag: noindex, nofollow` and `/robots.txt` disallows everything. Set `false` when this becomes the public `app.lawnotation.org` |
| `SMTP_URL` | empty: no app emails (assignment/invitation notices). Sign-in codes are sent by Keycloak and don't need it |
| `CITATIONS_API_KEY` | empty for now: legal-docs search (Rechtspraak/ECHR import) is unavailable until it is set |
| `MLBACKEND_URL` | empty for now: ML pre-annotation and the archives page are unavailable until it is set |

### Keycloak

The `lawnotation` client (realm `lawnotation`) allows
`https://next.lawnotation.org/api/auth/callback` and
`http://localhost:3000/api/auth/callback` as redirect URIs and
`https://next.lawnotation.org/*` after logout, next to the existing
`app.lawnotation.org` entries.

### pgAdmin

The database is not published. In the shared pgAdmin (project **PgAdmin** on
rice, already on the `coolify` network) register a server with host
`lawnotation-postgres`, port `5432`, database and user `lawnotation`, and the
`SERVICE_PASSWORD_POSTGRES` value from the Coolify environment variables.

### Backups

The `backup` service writes `pg_dump -Fc` files to the `pgbackups` volume once a
day and keeps the newest 7 (`BACKUP_INTERVAL_HOURS`, `BACKUP_KEEP`). Restore:
`pg_restore -d lawnotation --clean <file>` from inside the `db` container.

## Developing against it locally

```
docker run -d --name lawnotation-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=lawnotation -p 5432:5432 postgres:17-alpine
cd lawnotation-ui && cp .env.example .env    # fill AUTH_CLIENT_SECRET and AUTH_SESSION_SECRET
pnpm install && pnpm db:seed && pnpm dev
```

`pnpm db:seed` applies the migrations and loads `db/seed/dev.sql` (an editor
`editor@example.com`, an annotator `annotator@example.com`, a project with a span
and a hybrid task). Signing in through Keycloak with one of those addresses links
the account to the seeded row.

## Later: moving production over

Not done yet; for when this deployment has proven itself.

1. **Data.** `pg_dump --data-only --schema=public` from Supabase and restore
   into the Coolify database (table and column names are identical, so it loads
   as is; `legacy_backup` can come along with a plain dump of that schema).
   Before that, check that no two users share an email in different letter case
   (`users_email_lower_key` is unique), and decide about the 3 auth users without
   a `public.users` row.
2. **Accounts.** Nothing to import into Keycloak: the first time someone signs
   in at the new address with their email, `resolveUser` links their existing
   users row by that (verified) email. Copy `auth.users.raw_user_meta_data` into
   `users.metadata` if the onboarding state should survive.
3. **Switch.** Point `app.lawnotation.org` at rice (Vercel DNS), set
   `LAWNOTATION_URL=https://app.lawnotation.org` in Coolify, add
   `https://app.lawnotation.org/api/auth/callback` to the Keycloak client, set
   `NOINDEX=false`, freeze
   writes on the old app for the final dump, and keep Vercel + Supabase read-only
   for a while as a fallback.
4. **The rest of Vercel.** The landing page (`lawnotation.org`) and the docs
   (`docs.lawnotation.org`) are static sites that can become Coolify static
   apps; the `lawnotation.org` DNS zone lives at Vercel and would move last,
   with its Mailtrap records.
5. Update the privacy policy page, which still names Supabase as the database
   provider.

## Known gaps on this branch

- `lawnotation-ui/supabase/` (old migrations, config, email templates) is kept
