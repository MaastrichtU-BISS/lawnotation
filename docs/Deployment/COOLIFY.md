# Lawnotation on Coolify

The branch `feature/coolify-deployment` runs Lawnotation without Supabase or
Vercel, on the BISS Coolify (server **rice**), at
<https://next.lawnotation.org>. The production setup (Vercel +
Supabase, `app.lawnotation.org`) is untouched and keeps running; moving data
and users over and switching the domain is a later, separate step.

```
browser ──► app (Nuxt/Nitro, node)  next.lawnotation.org
              │  session cookie, own OIDC client
              ├──► Keycloak, realm lawnotation   auth.lawnotation.org (shared, not in this stack)
              ├──► IAA service                    iaa.lawnotation.org  (existing, not in this stack)
              ▼
            db (Postgres 17)  ◄── migrate (one-shot)   ◄── backup (nightly pg_dump)
              └── on the shared `coolify` network as lawnotation-postgres (pgAdmin)
```

## What replaced what

| Before (Vercel + Supabase) | Now |
|---|---|
| Vercel serverless function running the Nuxt server | the same Nuxt server in a container (`lawnotation-ui/Dockerfile`) |
| Supabase Postgres + PostgREST (supabase-js `.from()`, `.rpc()`) | plain Postgres 17; the server queries it with postgres.js (`ctx.sql`) |
| `supabase/migrations` | `lawnotation-ui/db/migrations`: `0001_baseline.sql` is the public schema those migrations produce, without the Supabase parts; `0002_oidc_users.sql` adds sign-in columns; `0003_queries_in_code.sql` drops the SQL functions. Applied by `scripts/migrate.mjs` on every deploy |
| SQL functions in the database, called by name (`supabase.rpc("get_all_docs_from_task")`), typed by the generated `types/supabase.ts` | typed TypeScript functions in `lawnotation-ui/server/db/queries` (`documentsOfTask(ctx.sql, taskId)`), versioned and reviewed with the code; the database keeps only tables, constraints and indexes. `documents.hash` is a generated column instead of a trigger |
| Supabase Auth (email OTP, magic links, `auth.users`) | Keycloak realm `lawnotation` (email + one-time code, its own mail), via `caselaw-auth/server`; the app keeps a signed httpOnly session cookie |
| `handle_new_user()` trigger on `auth.users` | `resolveUser()` in `server/utils/auth.ts`: links a users row to a Keycloak account by `oidc_sub`, or by verified email (invited annotators, migrated users), or creates a new editor |
| `auth.users.raw_user_meta_data` | `users.metadata` (onboarding hints, invitation flag) |
| `inviteUserByEmail` | the users row is created ahead of sign-in; the app emails the person if `SMTP_URL` is set |
| Supabase Studio | pgAdmin (the shared instance on rice) |
| Row level security (enabled, no policies) | none; every request is authorized in the tRPC authorizers, as before |

There were no Supabase cron jobs, Edge Functions, Storage buckets or Realtime
subscriptions, and no Vercel cron jobs, so nothing else had to move.

## Coolify resource

- Project **Lawnotation**, environment `production`, application `lawnotation`
  (Docker Compose build pack), public repository
  `https://github.com/MaastrichtU-BISS/lawnotation`, branch
  `feature/coolify-deployment`, compose file `/docker-compose.coolify.yml`.
- Domain: `https://next.lawnotation.org:3000` on the `app` service. The
  `lawnotation.org` zone (Vercel DNS) has a wildcard A record to rice, so no
  DNS change was needed.
- Pushes to the branch don't deploy by themselves (public repository without a
  webhook): use **Deploy** in Coolify.
- `lawnotation-ui/vercel.json` turns off Vercel builds for this branch, so the
  Vercel project never builds it against the production Supabase settings.

### Environment variables

| Variable | Value |
|---|---|
| `SERVICE_PASSWORD_POSTGRES`, `SERVICE_PASSWORD_64_SESSION` | generated by Coolify on the first deploy; don't change them |
| `AUTH_CLIENT_SECRET` | the `lawnotation` client's secret (Keycloak → realm lawnotation → Clients → lawnotation → Credentials) |
| `IAA_API_KEY` | the same key as the **Lawnotation IAA** application |
| `LAWNOTATION_URL`, `AUTH_ISSUER`, `AUTH_CLIENT_ID`, `IAA_SERVICE_URL` | empty = the compose defaults (`https://next.lawnotation.org`, the lawnotation realm, `lawnotation`, `https://iaa.lawnotation.org`) |
| `NOINDEX` | empty = `true`: every response has `X-Robots-Tag: noindex, nofollow` and `/robots.txt` disallows everything. Set `false` when this becomes the public `app.lawnotation.org` |
| `SMTP_URL` | empty: no app emails (assignment/invitation notices). Sign-in codes are sent by Keycloak and don't need it |
| `CITATIONS_API_KEY` | empty for now: legal-docs search (Rechtspraak/ECHR import) is unavailable until it is set |

### Keycloak

The `lawnotation` realm (shared Keycloak, admin console at
<https://auth.biss-institute.com/admin/lawnotation/console/>, front name
`auth.lawnotation.org`) signs people in with their email and a one-time code
(flow `caselaw-browser-passwordless-email-first`, codes mailed through the
realm's SMTP). Self-registration is off, but the email step creates an
unverified account for an unknown address and the code verifies it, so anyone
can still sign in; the app then links or creates their users row.

The `lawnotation` client (confidential, PKCE S256, standard flow only) allows
`https://next.lawnotation.org/api/auth/callback` and
`http://localhost:3000/api/auth/callback` as redirect URIs and
`https://next.lawnotation.org/*` after logout, next to the existing
`app.lawnotation.org` entries.

**Accounts from Supabase.** On 2026-11-24 all 677 Supabase Auth users were
imported into the realm (Realm settings → Partial import, "skip" on existing
users): username and email are the lowercased address, the Keycloak user id is
the Supabase user id, and *email verified* follows Supabase's confirmation
(365 of 677; the others are verified by their first code). 4 addresses already
had a Keycloak account and kept it. No mail is sent by an import. Supabase
passwords are not carried over: sign-in here is by code only. To add people
who signed up on the old app since, export again and import with "skip":

```sql
-- Supabase SQL editor; save the result as a JSON file
select json_build_object('ifResourceExists', 'SKIP', 'users', json_agg(json_build_object(
  'id', id, 'username', lower(email), 'email', lower(email),
  'emailVerified', email_confirmed_at is not null, 'enabled', true,
  'createdTimestamp', (extract(epoch from created_at) * 1000)::bigint)))
from auth.users where email is not null;
```

### pgAdmin

The database is not published. In the shared pgAdmin (project **PgAdmin** on
rice, already on the `coolify` network) register a server with host
`lawnotation-postgres`, port `5432`, database and user `lawnotation`, and the
`SERVICE_PASSWORD_POSTGRES` value from the Coolify environment variables.

### Backups

The `backup` service writes `pg_dump -Fc` files to the `pgbackups` volume once a
day and keeps the newest 7 (`BACKUP_INTERVAL_HOURS`, `BACKUP_KEEP`). Restore:
`pg_restore -d lawnotation --clean <file>` from inside the `db` container.

## Developing against it locally

```
docker run -d --name lawnotation-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=lawnotation -p 5432:5432 postgres:17-alpine
cd lawnotation-ui && cp .env.example .env    # fill AUTH_CLIENT_SECRET and AUTH_SESSION_SECRET
pnpm install && pnpm db:seed && pnpm dev
```

`pnpm db:seed` applies the migrations and loads `db/seed/dev.sql` (an editor
`editor@example.com`, an annotator `annotator@example.com`, a project with a span
and a hybrid task). Signing in through Keycloak with one of those addresses links
the account to the seeded row.

## Moving the legacy data

Two one-shot services copy the Supabase data into this database. The source
is one of Supabase's daily backups (Pro plan: Database → Backups → Scheduled,
"Download"), so the legacy project is only read and needs no database
password:

1. `legacy-restore` (`lawnotation-ui/scripts/restore-legacy-backup.sh`)
   downloads the backup from its signed link and loads only its `postgres`
   database (no roles, no other databases) into a scratch database
   `legacy_restore` on this server. About 450 statements about Supabase's own
   roles and extensions are skipped, as expected.
2. `legacy-import` (`lawnotation-ui/scripts/import-legacy.mjs`) reads that
   copy in one read-only snapshot and, in one transaction here:
empties the application tables, copies every table of the legacy public
schema (the columns both sides have; `documents.hash` recomputes itself),
fills `users.created_at`, `last_sign_in_at` and the app's metadata keys from
`auth.users`, copies the `legacy_backup` schema, moves the id sequences on and
compares row counts. Any failure rolls the whole run back (the scratch copy
is then kept to look into; after a successful run it is removed).
`users.oidc_sub` stays empty; each person's first Keycloak sign-in links their
row by email.

To run it, set in Coolify (runtime only, not build time) and deploy:

| Variable | Value |
|---|---|
| `LEGACY_DUMP_URL` | the backup's signed download link (what "Download" opens; valid 5 hours, treat it as a secret: it gives the whole database) |
| `LEGACY_IMPORT_RUN` | a new label, e.g. `2026-11-24-backup` |

Alternatively `LEGACY_DATABASE_URL` (the Supabase session pooler,
`postgresql://postgres.aukazbmquapjrmbhefkc:<password>@aws-0-eu-central-1.pooler.supabase.com:5432/postgres?sslmode=require`)
reads the live database instead of a backup; it takes precedence.

Both services run on every deploy but do nothing unless `LEGACY_IMPORT_RUN`
names a run that isn't in `public.legacy_imports` yet. **A new label replaces
everything created on this deployment since the last import.** Remove the
variables once the data has moved for good.

A backup is from around 01:00 UTC, so for the final move freeze writes on the
old app in the evening and import the next night's backup (or use the live
database with its password).

## Later: switching app.lawnotation.org over

1. Announce a short write freeze on the old app (or put it in maintenance).
2. Import the Keycloak accounts created since (above), then set a new
   `LEGACY_DUMP_URL` (a backup taken after the freeze) and `LEGACY_IMPORT_RUN`
   and deploy, so the final data comes over.
3. Point `app.lawnotation.org` at rice (Vercel DNS), set
   `LAWNOTATION_URL=https://app.lawnotation.org` and `NOINDEX=false`, add
   `https://app.lawnotation.org/api/auth/callback` to the Keycloak client,
   then remove `LEGACY_DATABASE_URL` and `LEGACY_IMPORT_RUN`.
4. Keep Vercel + Supabase as they are, read-only, for a while as a fallback.
5. The landing page (`lawnotation.org`) and the docs (`docs.lawnotation.org`)
   are static sites that can become Coolify static apps; the `lawnotation.org`
   DNS zone lives at Vercel and would move last, with its Mailtrap records.
6. Update the privacy policy page, which still names Supabase as the database
   provider.
